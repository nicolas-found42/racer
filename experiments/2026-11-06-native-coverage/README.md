## Blind Spots Identified

1. **Fixed, high diagnostic value:** `PlayFlow::observe` allocated state keys/fields outside a guard. Optional telemetry allocation could interrupt gameplay; a disabled sink still did the work. Acceptance: injected observer allocation failure must not escape, and a later retrieved state reports the lost observation.
2. **Fixed, high diagnostic value:** screenshot callback allocation could escape the renderer callback thread. Acceptance: injected failure returns safely, creates no partial capture in that injected path, and the next healthy capture has correct bytes plus a retained recovery count.
3. **Fixed, medium impact:** a free-drive boundary contact can exist for one 120 Hz tick and disappear before a 10 Hz motion sample; no state change necessarily records it. Acceptance: force contact and clear it on the next tick, then retrieve an independent edge event. Test-session invalidation reasons were already retained and remain so.
4. **Remaining, medium priority:** input normalization and sampled state cannot establish the exact physical controller/model/calibration or sub-sample key sequence. Do not infer hardware parity from virtual fixtures. Device correlation or a bounded opt-in input anomaly ring needs a separate privacy/reproduction design.
5. **Remaining, medium priority:** review scripts are explicit synthetic input but the ordinary runtime records only the enabled flag/cursor, not exact original script content identity. Retained experiment commands/scripts can supply it where actually archived; arbitrary later-edited scripts remain unknown.
6. **Remaining:** older renderer stderr details, exact historical livery/document content, arbitrary repeated screenshot bytes and unrecorded short-lived state cannot be reconstructed solely from opaque identities. Quota loss, missing recorder end and inaccessible files remain explicit unknowns, not success. ## What Changed

`PlayFlow::observe` is nonthrowing, skips unavailable diagnostics, preserves prior fields and retries a failed state after recovery. The next state carries cumulative `observation_failures`. A fail-open, rising-edge `boundary_contact` event records vehicle/attempt, pose revision, position/heading, requested normalized controls and resulting phase. Sustained contact does not emit per-tick events; reset starts a new encounter. Existing queue/run quotas still bound storage. A dropped edge remains possible under sink failure; no automatic diagnosis is promised.

`Capture::screenShot` is nonthrowing. Callback exceptions increment an allocation-free counter; the next successful `capture_end` carries `callback_failures`. Raw paths, image contents and arbitrary exception text are not added to telemetry. Successful capture behavior, quota and pixels are preserved.

Meaningful fixtures in existing `flow_checks` and `render_checks` inject thread-local allocation failure only around the observer/callback, leaving the asynchronous writer normal. They retrieve actual JSONL from temporary stores before cleanup and print the bounded relevant rows for retained root logs. The capture test also checks the recovered 1-pixel PPM bytes. These are CPU callback/state runtime fixtures, **not GPU callback scheduling or main-loop allocation-failure proof**. Root reports focused rebuilt flow/render plus lifecycle checks passed 3/3; direct retained logs and independent source review are root-owned and pending linkage here. This agent performs no build/GPU/focus actions.
