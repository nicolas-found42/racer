# Coverage inventory and diagnostic gaps

Scope: all first-party source, tests, scripts and build/configuration in this independent repository; source-game research remains retained documentary evidence, not runtime services. There is one native application process, an SDL input/event boundary, a bgfx render callback/worker boundary, a diagnostic writer thread, local profile/diagnostic/capture storage and external build-time downloads. There is no server, database service, network gameplay, job broker, account or production deployment (not applicable). Native renderer/OS/hardware internals are dependency boundaries, not asserted fully audited vendor implementations.

## Prioritized scenarios and acceptance

| Priority | Scenario / basis | Gap and diagnostic value | Acceptance |
|---|---|---|---|
| P0 | Reported car turns opposite camera — known human report | No shared transform check, no input/pose/model history | Real transform seam fails before fix and passes both signs/gate directions after; native turn sequences reviewed; retrieve model/travel/camera agreement. |
| P1 | Save fails, retry succeeds, app restarts — plausible and existing failure fixtures | Final profile cannot establish lost/delayed state or failure stage | Actual permission failure preserves bytes; distinct begin/end IDs and errno identify stage; retry succeeds and fresh recorder loads the saved record. |
| P1 | Focus/disconnect/pause with held inputs, unexpected test cancellation — known previous regressions | No past transition/rearm history | Live tests plus retained event/state/input sequence; query by run and attempt; no false claim of physical-pad coverage. |
| P1 | Timeout, boundary/reset, out-of-order gate attempts — test-covered hypothetical incidents | Invalid attempts absent from best-only profile | Invalid reason/attempt and record counts retrievable after process exit; wrong-order physics tests remain passing. |
| P1 | Crash/kill, queue saturation, quota or unavailable recorder — plausible | Silent history loss could masquerade as success | Query flags missing end/drops/truncated rows/quota; recorder failure does not stop benchmark completion; retained bytes bounded. |
| P2 | Screenshot failure or shader missing — real dependency boundaries | Output existed only on stdout or failed silently | Request/outcome pairing and dependency stage/hash; safely inject inaccessible capture destination/missing shader in isolated build/run. |
| P2 | Stalls/sampling gaps — human session had 1006.55 ms max interval, cause unknown | Aggregate maxima cannot locate or correlate a stall | Per-second timing/clamped-time counters and neighboring snapshots; hidden no-capture comparison, no root-cause claim from timing alone. |
| P2 | Duplicate/out-of-order profile operations, simultaneous app instances — hypothetical | No cross-run correlation; no storage lock | Stable profile identifier, run-local distinct operation IDs and chronological queries expose overlapping writes. Preserve existing last-writer-wins semantics; do not claim crash-safe multiwriter storage. |

Runtime observations and final acceptance are recorded in README.md. Instrumentation in this inventory is not itself proof of emitted, persisted or retrievable events; retained scenario stores and query outputs provide that proof.

## Preservation audit follow-up

[2026-11-05 preservation pass](../2026-11-05-observability-preservation/README.md) revalidates the above inventory against37 retained source/build hashes: only the offline query script and its Python tests change. First-party runtime coverage above is inherited from that exact source inspection and retained native evidence, not a claim that every vendor file was reread. The query/storage-tool area was freshly inspected and improved: wholly unreadable files now report damage, unterminated tails and inspection budgets are explicit, and `--bundle` preserves whole selected runs plus optional hash-matching captures with private permissions and bounded payload. Real save/reload/interruption stores were retrieved from bundles; tests move the original store and query the copy. Source/runtime identities remain in copied events. Current source and tool hashes, commands, observed results and gaps are recorded in the follow-up. External and human limitations above remain open.
