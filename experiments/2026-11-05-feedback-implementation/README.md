## Implementation and evidence method

`src/presentation.cpp` derives wording from garage drafts, typed profile persistence, immutable session snapshots and retained-record provenance. `ProfileStore` exposes New/Loaded/Saved/Failed/Disabled facts; `PlayFlow` retains the prior record and whether a valid finish changed the best. Serialization and matching are unchanged. Read-only session accessors identify braking lead-in/measurement and measured distance. Guidance derives relative bearing, distance, crossing direction and approach-side recovery from the existing gate/car data. Rendering has a dedicated context panel, highlighted selection, prominent valid metric, explicit partial invalid metric, compact active HUD and bottom course controls. Only the active gate gets a projected label, clamped below the HUD at small size.

`scripts/verify_feedback.py` creates a fresh output/profile, sends menu actions through SDL events using the opt-in `--review-script` driver, waits on real simulations, asserts visible text and captures renderer frames. It never inserts best records. The handling driver supplies synthetic steering/throttle/brake inputs from the existing course; this is **not human playtesting**. The driver can log and inject synthetic focus-gained/resume events during interrupted waits without taking desktop foreground focus; normal play and the separate focus-loss checks do not use that path. Each full loop has `--smoke 290` and a 295 s external watchdog. Each PPM is removed only after a PNG decode compares pixel-identical. The actual isolated profile directory is chmod 0500 for write failures and restored to 0700 for Retry Save; no normal player save is touched.
